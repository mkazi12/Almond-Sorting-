# SCRUM-48 storage services

The create/read services extend the schema and media store in [database.md](database.md).
They persist recordings, model versions, inspections, datasets, and training progress.
Callers own transactions; there are no Qt imports or inference/training workers here.

## Service contracts


Every storage operation takes a SQLAlchemy Session first; callers commit or
roll back. Creation/lifecycle times are generated by PostgreSQL and app
connections request UTC. Caller-supplied recording capture time must include
a timezone. Imported files are removed when their owning transaction rolls
back, including service savepoints. A hard process crash can still leave
unreferenced files; those are harmless extras, not missing registered media.

- `recordings.create_recording(session, store, name, files, ...)` accepts an
  ordered sequence of videos or images, in separate recordings. Video
  offsets sum rounded durations in milliseconds; still images have offset
  zero, no FPS/duration, and one analyzed frame each with `frame_index=None`.
- `model_registry.register_model_version(...)` takes `input_size=(width,
  height)` and category keys in model output order. Version numbers are
  serialized per family. Imported ONNX versions become READY;
  checkpoint-only versions remain DRAFT. Registration records bytes and
  metadata; it does not validate executable ONNX graph semantics.
- `inspections.create_session(...)` takes recording/model IDs, optional
  `category_keys`, interval, sample FPS, and confidence threshold. Omitted
  category selection means all model categories; an explicit empty selection
  is rejected. Only READY ONNX versions may create/start sessions.
- Inspections transition queued -> running -> completed/failed/cancelled.
  Queued sessions can also fail or cancel before starting; finished sessions
  cannot restart. A failure requires an error message.
- `save_frame_results` accepts `FrameResult` records or four-tuples
  `(media_file_id, frame_index, timestamp_ms, detections)`. Detections are
  `DetectionResult(class_index, confidence, box)` records, with pixel **xyxy**
  corners. The current UI mock returns **xywh** and named classes; an adapter
  must convert those before using this API.
- Media must belong to the recording. Video timestamps include the file's
  recording offset and must match the frame index within 1 ms. Unknown class
  indices, nonfinite/invalid values, and oversized boxes are errors. Edges
  within `1e-6` in normalized coordinates are clamped. Known detections below
  threshold or outside selected categories are excluded; empty frames persist.
- Duplicate frame keys retain the original results. Frame and detection
  insertion is atomic for an entire call. Call with batches of about 500
  frames, using a **new caller transaction for each batch** to bound crash
  loss. Internal chunking does not commit. Resume by resending the committed
  timestamp boundary and skipping duplicate media/frame keys, or use a cursor
  including media ID/frame index: several still images can share time zero.
- `get_session_summary` returns a dictionary containing IDs, timestamps,
  status, loaded model/recording, interval, frame count and category counts.
  Counts are per-frame detections, not unique tracked almonds. `list_sessions`
  uses newest-first deterministic order, optional name/recording search,
  model/date filters and limit/offset (limit 1..1000). `frames_between` uses
  the half-open interval `[start_ms, end_ms)` and loads media/detections.
- `datasets.import_dataset_version` maps the existing dataset records and
  version manifest. `category_map` maps `(annotation_relative_path,
  coco_category_id)` to a registered category key. COCO boxes use pixel xywh;
  their image association includes annotation-file identity. Rejected records
  and accepted negatives persist. Split remains unset: eligibility is not
  an assigned split. Freeze a version before using it for training; reimport
  changes under a new version label. No service mutates frozen images.
- Training: create -> `start_training_run` -> consecutive `record_epoch`
  calls -> `finish_training_run`. Epochs cannot repeat or skip. `is_best=True`
  records the worker's chosen best epoch. Completed runs need all epochs.
  `request_stop` moves running -> stopping; the worker later finishes stopped.
  A queued run stops immediately without a start time. This is persistence
  support; no model-training worker is launched by these APIs.

## Acceptance checks

Use Python 3.12 with the existing requirements and PostgreSQL 18. Follow
[database setup](database.md) before running the checks. Tests create and remove
only their own `dinos_test_*` databases; the database role needs CREATE DATABASE.

```powershell
$env:DINOS_REQUIRE_DB = '1'
$env:QT_QPA_PLATFORM = 'offscreen'
python -m pytest -q tests/test_storage_services.py
python -m pytest -q -s --run-slow tests/test_storage_performance.py
```

The service tests cover exact committed ID/path/timestamp reopening on a new
engine, UTC lifecycle times, legal states, category selection, archived model
rejection, duplicate and atomic frame saves, pixel/normalized conversion,
dataset provenance and freezing, training epochs/stops, concurrent version
allocation, and file cleanup on transaction rollback.

The benchmark saves 28,800 frames with 576,000 detections and commits every
500 frames. It verifies exact counts and requires save time under 60 seconds.
The benchmark media bytes are a metadata fixture, not an executable video.

SCRUM-49 builds on these services to add samples, media verification and
backup/restore. Its recovery commands and tests belong to the dependent PR.

## PR branch validation

On Python 3.12.10 and PostgreSQL 18.6, after updating to the latest main:
**222 tests and 35 subtests passed** in 38.90 seconds. The two Windows-only
checks were skipped, and the slow benchmark was run separately.

The isolated benchmark passed in **57.75 seconds**, with exact counts and
caller commits every 500 frames. An earlier full-suite run measured 74.31
seconds and exceeded the 60-second threshold; timing depends on workstation
load. The missing-database diagnostic test passed on the same isolated rerun.
